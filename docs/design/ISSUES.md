# Tickets GitHub proposés

À créer dans l'ordre. Chaque ticket renvoie à la section correspondante du README.

1. **Setup** : générateur statique, tokens CSS, polices auto-hébergées, noindex, robots.txt. *Label : infra*
2. **Modèle de contenu** : collection `specimens` (JSON ou Markdown), séries, statut pending. *Label : contenu*
3. **En-tête et pied de page** : logo et étiquette, liens soulignés d'un trait tremblé, menu sous le logo. *Label : ui*
4. **Mode nuit** : bascule, localStorage, prefers-color-scheme, planches toujours claires. *Label : ui*
5. **Accueil** : dernier spécimen, état « en cours d'observation », liens manuscrits, grille de 2 colonnes. *Label : écran*
6. **Page planche** : cartouche accroché, image responsive, légende sous l'image, signature, précédent / suivant. *Label : écran*
7. **Fiche espèce** : dessin annoté (annotations positionnées en %), 4 rubriques. *Label : écran*
8. **La collection** : grille de 2 colonnes, filtres par série, état vide, compteur. *Label : écran*
9. **À propos** et **404**. *Label : écran*
10. **Accessibilité** : focus visibles, textes alternatifs, contraste ≥ 4.5:1, cibles tactiles ≥ 44px. *Label : qualité*
11. **Assets finaux** (auteur) : scans, signatures, logo lettré à la main. *Label : dessin*

Pour suivre les dessins dans GitHub : un ticket par spécimen, avec le label `dessin` et une checklist (croquis → encrage → scan → fiche rédigée → publié). Un champ « numéro » dans un Project board donne le statut `pending` du modèle de contenu.
